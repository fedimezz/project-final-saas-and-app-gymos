# GymOS — changes of 2026-10-09

Two projects: `saasssss-club-updated (1)` (Next.js SaaS + API) and `app_gymos-production (1)` (Expo app).

## Deploy steps
1. Web: `npx prisma migrate deploy` (new migration `20261009000100_push_tokens_public_offers_hero_model`), then deploy.
   Optional env var: `EXPO_ACCESS_TOKEN` (see `.env.example`).
2. Existing promotions become **private** after the migration (they were never shown anywhere). Owners re-tick
   "Afficher sur le site du club" on the offers they want public; new offers are public by default.
3. Mobile: run `eas init` once so `app.json` gets `extra.eas.projectId` (push tokens cannot be issued without it),
   then build a **development/production build** — remote push does not work in Expo Go on Android.
   Without a project id the app keeps working and shows no push prompt.

## 1. Bugs
- `accept-invitation`: no more `borderColor`/`borderTopColor` mix. Root cause of the endless reload: the client trusted a
  stale localStorage copy of the login. `AuthContext` now always reconciles with `/api/auth/session` (8 s timeout, clears a
  stale copy, server wins); invitation/verify/login pages save the verified identity and use `lib/post-login-path.ts`
  (coach → `/dashboard/coach`). `/api/auth/session` also rejects sessions revoked by a password change.
- Dashboard: 15 s timeout, 401 → clean sign-out + login, retry button, no setState after unmount.
- Test/lint baseline repaired: auth cache leaked between tests (`clearAccountCache`), outdated logo URL in a test,
  `eslint-config-next` aligned to Next 16 (^16.3.0), 2 lint errors fixed.

## 2. Activity Log
Owner-only: `GET /api/admin/logs` uses `requireOwner`, `/admin/logs` + `/api/admin/logs` are in the proxy owner-only list,
page wrapped in `OwnerOnly`, sidebar entry hidden for ADMIN. SUPER_ADMIN reads club logs via `/api/platform/logs`.

## 3. Coach app
Sessions, planning, rosters, attendance and stats were already wired to real endpoints. Added:
`GET/PATCH /api/dashboard/coach/profile` (name, phone, bio, specialties; saved on the Coach row the public page reads AND the
user row, one transaction; owner switch `coach.profile.edit`) and a coach profile editor in the app.

## 4. Push notifications
Server: `DeviceToken` table, `POST/DELETE/GET /api/devices` (auth, member/coach only, token format check, rate limit, per-user
device cap, token re-assigned when another account signs in on the phone, tokens masked in GET), `lib/push.ts` (Expo Push API,
chunks of 100, dead tokens deactivated, respects the user's push preference, never throws). Sent for: announcements,
schedule changes (plan activation/deletion, session edits), bookings/cancellations (member + coach), news posts, and the
07:00 daily session reminder (members + coaches).
App: `expo-notifications`/`expo-device`, in-app prompt before the system dialog, Android channel, token registration,
unregister on sign-out, tap → opens the right tab (also from a closed app).

## 5. Dark mode
Semantic tokens kept as the single source; added a safety layer (`globals.css`) mapping legacy light-only utilities to tokens,
`color-scheme`, native `<select>` options, placeholders, autofill, focus rings; AA status-text tokens (`--success-fg`, …) and a
darker light-mode muted text. `lib/__tests__/theme-contrast.test.ts` checks WCAG ratios of the real tokens in both modes.

## 6. Public pages
There was no public endpoint for promotions at all. Added `GET /api/promotions/public` (tenant from host, active + published +
in date window + uses left; end date inclusive), `Promotion.isPublic`, admin toggle, offers section on `/offres` and on the home.
Coaches public API verified by tests (club scoping, active only, no private fields).

## 7. Website customization
Five complete themes (Musculation, CrossFit, Boxing, Yoga & Bien-être, Fitness Moderne): own hero layout, section order,
dividers, self-hosted fonts, shape, motion and default 3D object. 8 procedural 3D objects (dumbbell, kettlebell, barbell, boxing
glove, weight plate, medicine ball, punching bag, zen stones). Owner page `/admin/appearance`: theme previews, live 3D preview,
model choice, logo upload, primary/secondary colors; saved per club in `GymSettings` (`themeId`, `heroModel`, colors, logo).
Old theme ids (classic, energetic, nature, midnight, minimal) are mapped to the new ones. Home sections no longer use
hard-coded navy/lime; they follow the club's brand colors.
