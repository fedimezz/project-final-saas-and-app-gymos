# ClubX — changes of 2026-10-12

## Members
- A member promoted to COACH or ADMIN now STAYS in Admin → Membres (before, the list only returned role MEMBER).
  - `GET /api/admin/members`: OWNER sees MEMBER + COACH + ADMIN; ADMIN sees MEMBER + COACH (never another admin).
  - New optional `?role=` filter, role filter chips in the page, and a Coach / Admin badge next to the name.
  - The role modal opens on the member's current role. Deleting an ADMIN from this list is not offered.

## Themes and 3D
- 5 new themes (15 total): Noir & Blanc, Sunset Energy, Ocean Aqua, Royal Violet, Forest Outdoor. Original 10 ids unchanged.
- New 3D choice "Haltère d'origine" (`dumbbell-classic`): your original dumbbell, loaded from `public/models/dumbbell.glb`.
  If the file cannot load, the built-in dumbbell is shown instead.

## Comments (web + phone)
- API: rate limit (20 per 10 min per user), the activity log can no longer turn a saved comment into a 500 (which made users post twice), authors can delete their own comments (staff still moderate with `announcements.manage`).
- Web (member news page + admin news page): errors are shown, text is kept if sending fails, author delete button, Enter key ignores IME composition.
- Phone: author can delete own comment; the card refreshes comments/likes after a pull-to-refresh.

## Rename + landing
- Product name is ClubX in the web UI, `app.json` (slug `clubx-mobile`, scheme `clubx`, bundle id `com.clubx.mobile`) and `package.json`.
  Internal storage keys (`gymos.*`) were left as they are on purpose so signed-in users are not logged out by the rename.
- New black & white landing page (`components/landing/*`, `app/landing-mono.css`) with a moving background (`LandingBackground.tsx`:
  drifting grid, soft orbs, pointer-reactive constellation; pauses when the tab is hidden; still frame with reduced motion).

## ClubX mascot (added later the same day)
- Original brand character: a muscular cartoon athlete (buzzed hair, headband with an X, white tank top with a bold X, black shorts).
  Drawn from scratch as SVG — `saasssss-club-updated/components/brand/ClubXMascot.tsx` (`ClubXMascot` full figure, `ClubXMascotMark` round logo badge).
- Landing page follower — `components/landing/LandingMascot.tsx`: walks along the bottom edge following the mouse (spring easing), eyes/head look at the
  pointer, body leans into the movement, click/tap = flex + "Allez !". On touch it follows the finger and drifts with scroll.
  Never blocks clicks (pointer-events: none), pauses on hidden tab, stays still with "reduce motion", hidden when printing.
- Logo mark replaces the generic dashboard icon in the landing navbar and footer.

## Mobile app: ClubX brand first, then the club's own brand, theme and 3D hero
- **Before a club is chosen** (launch, "Mes salles", club search): the ClubX mascot badge + wordmark (`ClubXBrand`, `ClubXMark`).
- **Inside a club**: the club's logo + name, its theme colors (already applied), and its **3D hero object** on the member home and coach "Aujourd'hui"
  (`ClubBanner` + `ClubHero3D`). Login screens show the club's logo/name with a small "Propulsé par ClubX".
- The club owner stays in control from the website: theme, colors, logo, 3D object (built-in list, "Haltère d'origine", or their own .glb/.gltf upload
  with scale/rotation/position) — the app reads the same public settings (`/api/settings/public`) and refreshes within a minute. A club that turns the 3D hero off gets the banner without it.
- Brand state: `src/brand/BrandContext.tsx`; `ThemeSync` now caches the whole identity per club (instant launch, no flash) and clears it when no club is selected.
  `src/lib/clubBrand.ts` validates everything the server sends (colors, logo scheme, theme id, 3D id, custom-model size/path/format, transform ranges).
- **How the 3D works**: one small WebView page built from the website's own three.js model code (`hero3d-viewer/entry.ts` + `scripts/build-hero3d.mjs` →
  `src/hero3d/viewerHtml.generated.ts`, committed). Same objects, colors and motion as the website, no network needed for built-in objects.
  Re-run `npm run build:hero3d` only when the website's 3D models change (reads `../saasssss-club-updated`).
- **Optimization**: viewer loaded lazily after the screen animates in; render loop stops when the screen loses focus, the app goes to the background or "reduce motion" is on;
  pixel ratio capped and lowered automatically on slow phones; custom model capped at 3 MB, downloaded once per version (content-hashed URL, memory only, no session token sent);
  the page has a content-security policy that blocks all network requests; if 3D cannot run the logo/icon fallback stays — never an empty hole.
- New dependencies: `react-native-svg`, `react-native-webview` (versions taken from Expo's own SDK list), dev: `esbuild`. WebView works in Expo Go.
- Checks here: tsc clean, eslint clean (`--max-warnings=0`), 46/46 tests (11 new: payload validation, hero plan, base64).
  The 3D page itself was rendered in headless Chromium for 8 cases (built-in objects with club colors, original dumbbell, custom upload with transform, broken file → fallback, unknown id → fallback).
- **Not verified**: on a real phone (WebView + WebGL on Android/iOS), the app's React Native screens visually, a real custom-model download from a club host.
  Please test on a device with: a club with a built-in object, one with 3D off, one with an uploaded model.
- Native app icon and splash screen: now the ClubX mascot (see the last section). The app tab icons are unchanged.

## Last "GymOS" names removed
- Mobile project folder `app_gymos-production` is now `clubx-mobile`. If your editor or terminal is open in the old folder, reopen the new one.
- Web npm package name `club` is now `clubx-web`.
- Old report titles, example domains (`gymos.com` -> `clubx.com`) and test sender names now say ClubX.
- Kept on purpose: internal storage keys that start with `gymos.` / `gymos:` (phone and browser). Renaming them would sign every user out and reset saved clubs. Users never see them.
- The GitHub repository name is yours to rename in GitHub settings; the commit history keeps the old folder name.
